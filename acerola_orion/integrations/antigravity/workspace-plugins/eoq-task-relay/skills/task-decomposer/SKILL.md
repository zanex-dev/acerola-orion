# Task Decomposer（EOQ 先读后拆与轻载接力协议）

将**高熵全局探索**与**低熵定点施工**物理拆窗，守住 200K 上下文红线；产物严格兼容 `Acerola-Orion` 任务看板机读规范。

## 模式 A：只读探索与拆解（Planner · 默认第一步）

1. **严格只读业务源码**：禁改任何项目源码、配置或测试；唯一写入目录为 `<workspace>/.agents/tasks/<YYYYMMDD_HHMM>_<英文短slug>/`（无工程目录时写入当前 Artifact 目录 `tasks/`）。
2. **一次性读透、进场前排雷**：
   - 先直读源码、配置与测试基线；仅当存在影响架构方向的关键歧义时提出 `≤3` 个问题，否则直接落盘；
   - **重构卡门槛**：探索窗承担唯一一次全仓引用扫描，把完整受影响调用清单写死到各卡片中，严禁留给执行窗再扫；
   - **修 Bug 卡门槛**：必须先完成排障并锁死**复现命令 + 根因文件行号 + 修复方案**才准开施工卡（尚未确诊前留在探索窗继续诊断，禁开盲修卡）；
   - **单卡同样落盘**：即使最终只拆出 1 张 `T01`（例如经过大量排查才定位的 3 行 Bug），只要探索窗已吃进大量脏上下文，仍须落盘为 `T01` 换干净执行窗施工。
3. **EOQ 自包含切片标准**：
   - 每张卡仅触碰 **1~4 个强关联文件**，预估单窗 **60K~95K** 内可闭环（施工 + 验证 + 回执）；
   - 标明前置依赖与并行组（`P1/P2/...`：同组无文件冲突卡片可多窗并行）；
   - 每张卡 **≤ 1.5K Token（约 2,400 字符）**：须包含**精确行号白名单**、**≤10 行内联关键签名/类型骨架**、**已排雷/免查声明**与**硬验收命令**，严禁贴大段业务源码。
4. **落盘即停与三段人话导航**：写完 `PLAN.md` 与 `T01~Tn` 卡片后，**立即结束回合**，严禁在同一窗口顺手改业务代码；停手回复必须包含三段大白话导航：
   - **① 这是做什么的**：用人话讲清整包解决什么问题、最终效果与各卡用途，禁堆黑话；
   - **② 怎么执行**：标明首批就绪卡、并行/串行顺序，提示可在看板双击就绪卡启动，并附可直接复制的启动口令；
   - **③ 执行完之后你该做什么**：说明单卡跑完后接哪张/哪批卡，以及整包全 `[x]` 后的实操验证/使用步骤与封版（`version-seal`）提示。

## 模式 B：轻载精准执行（Worker · 只认卡片）

1. **免读总计划、只认单卡**：启动与施工阶段**不读 `PLAN.md`**，只读目标 `T0x_*.md` 及其顶部标注的直接前置卡「`## 5. 执行回执`」；若前置卡回执非已完成状态，先向用户确认。
2. **白名单定点读、严禁全仓盲搜**：严格按第 2 节 `StartLine/EndLine` 切片读取靶区；**严禁列目录、全仓 `grep`、整文件通读或顺 `import` 链向上层翻查**。
3. **越界补读熔断阀（≤ 2 次）**：若卡片确有遗漏定义，最多允许 **≤ 2 次**精准行段补读；若超出 2 次仍缺上下文、或验收报错指向卡片范围外的根因，**立刻停止施工并熔断**——在 `T0x` 回执记为 `[~]` 并输出 ≤8 行《缺料单》（缺哪块信息 / 报错摘要 / 建议回探索窗核查点），**严禁在执行窗内就地开启全仓排查**。
4. **回执、最小化打勾与三段人话收尾**：验收命令全绿后（受环境限制处须明示），回填 `T0x_*.md` 第 5 节回执（≤8 行）；**仅在收尾打勾时**精确修改同目录 `PLAN.md` 进度表中对应 `T0x` 行（`[ ]` -> `[x]`，不通读背景段）。停手前必须输出三段大白话收尾：
   - **① 刚做完了什么**：用白话总结本卡交付改动与实测验收结果；
   - **② 接下来你该做什么**：结合刚更新的进度表与卡内「完成后下一步（给用户）」，点明下张/批解锁卡的用途并附可直接复制的启动口令；若整包已全 `[x]` 结项，给出端到端实操验收/使用步骤与 `version-seal` 封版提示；凡需用户手动配合的动作须显式列出；
   - **③ 单步停顿**：汇报完毕后**立即停下来等用户确认**，严禁越步执行下一张卡（若逼近 `95K+` 未完，标 `[~]` 并走 `stage-handoff` 续接）。
